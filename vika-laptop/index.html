A local AI for a laptop on its last legs

A small, private chat model for a friend’s 8 GB Windows laptop — what I tested, what it proves, and the one cheap upgrade that would do the most good.

Vika’s laptop is a Lenovo IdeaPad S340-15IML: an i5-10210U with four cores, 8 GB of RAM, and a 2 GB GeForce MX230. It is tired but not finished. The plan is GobboNet — a free, open-source local chat front end that runs the model on the machine itself: no account, no cloud, no bill, and after setup, nothing leaves the laptop.

What I actually did

I didn’t want to hand over a link and hope. So I put GobboNet on the lab bench first.

  • Installed GobboNet 1.8.1 on SPL (the Linux build) and read the Windows launcher and hardware-probe source, because her machine is Windows.
  • Its own engine download is a glibc build and SPL is musl, so on the bench I pointed GobboNet at SPL’s native llama.cpp instead. The front end, character cards, config panel and model catalogue are the same program either way.
  • Ran Llama 3.2 3B Instruct, Q4, at a 4k context with quantised KV cache, CPU only, two threads — deliberately the same shape as the plan for her laptop.
  • Measured a real chat round-trip through GobboNet’s own proxy, and read the code that decides which model her machine will be offered and how it will be launched.

What it proves — and what it doesn’t

It proves that a 3B model on a box with no usable GPU is real chat speed, not a demo; that GobboNet’s interface, characters and settings work on modest hardware; that a 2 GB laptop card is enough to take a slice of the work; and that the app’s own probe will correctly recognise her machine as CPU-only and offer the 3B — the right model for it.

It also proves the trap. The same 3B is launched by default at a 32k context with an f16 KV cache — about 3.7 GB of cache by itself. On an 8 GB laptop already using 8.4 GB of page file at idle, that is a stall or a failed load. Starting it at 4k with q8_0 cache is the fix, and it is one panel in the app.

It doesn’t prove the Windows installer on her exact unit, the health of her disk, or her network — I can’t reach those from here. It also doesn’t prove a 3B model is clever enough for everything she might want; it is the honest ceiling of this machine, and it is a decent one.

Two prompts that default the wrong way

1. “Download it anyway?” defaults to no. Her card has 2 GB of video memory; the recommended model asks for about 6. The launcher warns, then asks — and pressing Enter means no, which drops back to the model list and looks like nothing happened. She has to type Y.

2. The first launch is too big for 8 GB. The context and cache settings have to be lowered before the first real conversation, or the laptop will thrash. The steps below put that before “say hello”.

What she has to do herself

Everything below is hers to run — I can’t install software on her machine from here, and I wouldn’t want to. It is one installer, one model download, and two settings.

  1. Download and run the installer. Windows will warn about an unsigned app: More info → Run anyway. The maker’s own page explains why it gets flagged, and the message below includes the Defender exclusion if the download is quarantined.
  2. Set a password for the local chat (8+ characters, not reused anywhere).
  3. Let it fetch the engine when asked — type Y.
  4. Take the recommended model (3B) — then type Y at the “only 2 GB VRAM, download anyway?” prompt, because Enter means no.
  5. Lower the context before chatting: CONFIG → Model & Performance → Context size 4096, KV cache q8_0, SAVE & RESTART MODEL.
  6. Say hello. The first reply takes 10–30 seconds while the model warms; after that a few seconds each.

**6.** It checks your hardware and shows a model list. **Press Enter** for the recommended

**7.** When the chat opens in your browser, **before you type anything**: open **CONFIG** →

needs roughly in half, and your laptop has 8 GB, not 16. Without it, the first reply may
stall or the laptop may crawl.

**8.** Say hello. The very first reply can take 10–30 seconds while it warms up; after that
it should be a few seconds each.

**Notes**
- If the laptop feels like it's dying: close other apps and browser tabs first. If it's still
  struggling, go to CONFIG → **Add a Model** → **Llama 3.2 1B** (1.3 GB). Quicker, simpler,
  less clever — a good trade on a tired machine.
- If it ever says it can't load the model: CONFIG → Model & Performance → set **GPU** to
  **None** (everything on the processor) and **SAVE & RESTART MODEL**. Slower, but it loads
  almost anywhere.
- Once it's set up you can unplug the internet and it keeps working.
- **Its memory of you:** a character's name, pronouns and personality live in its character
  card, so they're in every conversation — it can't forget them. If you already have a

The hardware recommendations

The easy one: RAM

Her laptop has 4 GB soldered and one free SO-DIMM slot, officially good to 12 GB (4 + 8). One 8 GB DDR4-2666 stick is the cheapest meaningful upgrade this machine can take, and it changes more than the AI: Windows stops leaning on the page file, the browser stops evicting itself, and a 3B model at a small context fits beside normal work instead of fighting it.

Worth knowing: 4 + 16 = 20 GB usually works on this generation but is outside Lenovo’s published spec. If she wants certainty, 12 GB is the documented maximum.

Check the disk before spending

The S340-15IML shipped with either a 2.5-inch 5400 rpm hard drive or an M.2 SSD. If her system drive is the spinning one, an SSD is the bigger win — for everything, not just the AI. A model has to be read from that disk on every launch; on a 5.4K drive the wait is the whole experience.

Don’t bother with the GPU

The MX230 is soldered to the board; there is no upgrade path, and a 2 GB card would not change the plan anyway. The 3B model at a 4k context is the right size for this machine either way — RAM makes it comfortable, not bigger.

What RAM does not do: make a 7B model pleasant. Speed is bound by memory bandwidth on a machine like this, not by free space. The right answer stays a small model, held in memory.
